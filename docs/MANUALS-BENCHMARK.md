# 复杂 GUI 操作手册：最小对照测试集

更新：2026-10-28。测试代码与隔离实验，不进入用户界面，不升级本机预览。

## 先回答“哪一个最有用”

当前产品的目标是把复杂操作转成下一次可检索、可理解的手册。Microsoft UFO 的演示语义提炼最贴近这一目标；OpenAdapt 提供动作/截图对齐的采集思路；Workflow Use 更适合可程序化的浏览器执行。它们分别覆盖不同环节。此处的选择依据是功能契合度；本实验没有安装三个上游产品进行排名。

## 要验证的假设

保留“页面、目标名称、动作、结果状态”的手册，比只保留动作种类的手册，更能传递用户专属流程。成功标准包含实际最终页面、准确实例、筛选条件及错误目标处理，加载事件不单独算成功。

### 三种材料

1. **none**：无手册，作为模型原有能力的对照。
2. **lossy**：当前产品从动作白名单生成的手册。来源截图、目标文字和页面状态被排除。
3. **semantic**：同一演示的动作白名单，附加已审阅的可见目标名称、页面标题和结果状态，再通过同一个编译器生成手册。

后两组使用相同名称、检索描述、输入参数、执行模型、工具和预算。语义材料由测试页面的事件记录采集，尚未验证模型从纯截图自动提炼语义的质量。它代表候选输入信息结构，不能直接等同于 UFO 原版效果。

本次来源演示和 lossy 草稿由 Sol 完成。semantic 首次 Sol 请求上游失败，保留 unknown；用户随后指定 Terra，在同一 Task、同一决定上授权重试一次，Terra 成功生成草稿。九个执行单元统一使用网关实际提供的 `openai/gpt-6.1-terra`。编译模型不同是本次实验的混杂因素，不能把全部差异归因于输入表示，也不重跑已成功的来源和草稿。Terra 无已配置价格的成功请求仍按未定价保留，已收到回执与费用未知分别统计。

## 来源与三个案例

来源是独立真实 Sol 任务在合成云控制台演示一次交接核查：华东一 / db-demo-101，进入归档日志，选择最近30分钟、仅异常并应用。保留原模型调用、实际 GUI 动作、截图和可见事件。没有真实云账号、付费资源或配置变更。

| 案例                       | 与来源的变化                                       | 独立验收                                                |
| -------------------------- | -------------------------------------------------- | ------------------------------------------------------- |
| deep-navigation            | 换地域、换实例；有相似 ID 诱饵                     | 在华北二 / db-eval-209 的归档日志页面；没有访问错误实例 |
| policy-and-layout-transfer | 同时换成顶部导航、重排页签；用户只给“交接核查”目标 | 找对实例，选最近30分钟和仅异常，真正点击应用筛选        |
| missing-instance           | 目标 db-missing-999 不存在，保留其他实例           | 先检查指定地域的实例列表，再停止询问；不打开其他实例    |

规则与评分器保留在宿主测试代码，不放进页面 HTML 或客体脚本。客体只提供通用 UI、可选过滤项及实际状态；“交接核查”的专属组合只出现在来源演示及由其生成的手册中。

## 控制变量与评分

- 3案例 × 3材料，共9个测试单元；每单元一次，不宣称统计显著性。
- 三组的顺序按案例轮换。每次新会话、新页面状态，没有历史对话或记忆。
- 普通任务没有指定 manualId，也没有“参考手册”的提示。是否主动 load_manual 单独记录。
- 仅通过实际容器桌面截图和键鼠操作；不能使用 DOM、Shell、文件读写或浏览器脚本。
- 页面返回的实际状态、事件和模型动作分别留证；完成状态或完成文本不替代检查。
- 记录成功率、GUI动作、模型决定数、耗时、错误实例访问、提问和加载情况。
- 对未解决的普通提问不提供答案，记下结果后通过原取消链结束该测试。未知模型费用/效果立即停止整个实验，不自动重试或另建 Task 绕过。

## 运行

```bash
# 0.6.3 基础镜像缺少中文字体；只构建隔离实验镜像，不覆盖主工作站
docker build -f tests/fixtures/Dockerfile.manuals -t owndesk-workstation:manual-benchmark-cjk .

# 纯逻辑评分器检查，不调用模型
npx tsx --test tests/manuals-benchmark.test.ts

# 实际网页点击/状态接口检查，不调用模型；需要本机 Chrome
npx tsx --test tests/manuals-benchmark-fixture.ts

# 真实模型演示与两份草稿；完成后暂停，检查草稿
npx tsx tests/manuals-benchmark.ts --prepare

# 只在创建 Task 之前的夹具启动失败时，继续同一隔离目录
npx tsx tests/manuals-benchmark.ts --prepare <实验目录>

# 仅供本次已收到的 Terra 单次重试授权；保存原快照，在原请求链上继续
# 授权已使用，重复执行会拒绝；后续检查不调用这个入口
npx tsx tests/manuals-benchmark.ts --terra-retry <实验目录>

# 检查两份草稿后，保存并运行九个单元
npx tsx tests/manuals-benchmark.ts --run <实验目录>
```

报告入口：`docs/evidence/manuals-benchmark.json`。时间戳报告、失败日志、原草稿、源演示和每单元截图留在报告指定目录。主库、.env、6797/6798、主工作站和原历史费用保持。

## 已完成的前置验证

- 独立评分器定向单元与三场景真实浏览器点击/状态检查通过。
- 原缺字体试验耗尽 30 个动作后按原取消链结束；30 次完整回执、费用和失败截图保留，排除于九单元比较。
- 添加字体后来源演示一次完成：12 次请求、11 个实际 GUI 动作。最终截图与页面状态均确认指定实例、归档日志、最近30分钟、仅异常、已应用。
- lossy 草稿一次成功，正文明确缺少具体路线和核查清单；semantic 原任务经用户授权的 Terra 单次重试成功，正文保留路线、筛选和参数。两份原始草稿已检查。
- 历史 unknown 原样保留；继续执行要求原复核请求已解决，并且同决定的后续请求确实成功，不能通过创建替代 Task 绕过。

## 结论边界

本轮测量语义信息是否对复杂流程复用有帮助。真实阿里云、跨网站/桌面软件泛化、纯截图自动提炼、人类接管教学录制及长期失效维护分别需要后续验收。

## 本次实际结果（2026-10-28）

每格只执行一次，无失败重跑。九个执行单元均为 `openai/gpt-6.1-terra`，全部实际动作均为桌面截图/键鼠，无 DOM、Shell 或文件脚本捷径，均没有进入错误实例。两份手册在对应六个单元中均由模型主动加载；加载成功与任务成功分开计分。

| 场景                            | 无手册                  | 旧版 lossy          | 语义 semantic           |
| ------------------------------- | ----------------------- | ------------------- | ----------------------- |
| 换地域、换实例的栏目导航        | 通过；8决定/7动作       | 通过；9决定/7动作   | 通过；9决定/7动作       |
| 私有交接规则＋顶部布局/页签重排 | 未完成；12决定/11动作   | 未完成；7决定/5动作 | 通过；13决定/11动作     |
| 实例不存在，检查后暂停询问      | 未进入询问；5决定/4动作 | 通过；6决定/4动作   | 未进入询问；6决定/4动作 |
| 严格通过数                      | **1/3**                 | **2/3**             | **2/3**                 |

### 最有价值的发现

1. **普通导航无需手册也能完成。** 此项三组都成功，不能将加载记录当作手册必要性的证据。
2. **具体语义能传递用户专属流程。** 用户只要求“按我的交接核查流程”，没有重复筛选条件。语义组在新布局、新地域和新实例下，按当前截图找到归档日志、最近30分钟、仅异常，并真正应用筛选。最终截图、独立状态和9条页面可见事件一致。旧版手册明确缺少步骤，模型请求补充清单；无手册组也请求提供流程。
3. **语义版的异常交互仍有缺口。** 三组都检查了指定地域列表、发现目标不存在、没有进入其他实例。旧版使用 `ask_user`，语义版和无手册版使用 `complete_task` 报告无法继续。语义版摘要还要求核对实例 ID，但系统已进入 completed，未保持等待答复。按预先定义的标准，后两项判失败，保留原结果。

因此本轮支持继续构建“具体操作语义＋明确异常分支”的手册，尚不支持语义版全面优于旧版，也没有证实减少总调用或总费用。下一步应把缺失目标等阻塞条件写成明确的“条件→停止→ask_user→等待答复”流程，并验证从实际截图提炼这些内容的质量。
