# Companion · Stage B2a：发图片给她、相似笔记确认卡

设计来源：`owndesk_stage_b_design.md` 的 B2a。两件事的共同原则：**图片和记忆都是你的私事**，
她不会悄悄把不该存的东西存下来，也不会擅自合并你的笔记。

## 1. 发图片给她

### 入口

| 渠道             | 做法                                                                                                                                                            | 状态                                           |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| 网页             | 输入框左边的“＋”选图，先上传、可预览和取消，再连同文字一起发送                                                                                                  | 已实现，浏览器测试 + 真模型验证                |
| Telegram         | 收到 `photo`（取最大尺寸）或 `image/*` 的 `document`，由 worker 经 `getFile` 下载；说明文字当作文字                                                             | 已实现；用假 Bot API 验证，**未用真 Bot 验证** |
| QQ（官方机器人） | 解析 `attachments` 里 `image/*` 的 `url`（QQ 的 url 常不带协议，会补 `https://`）                                                                               | 已实现并用假 QQ 事件测试；**未用真机器人验证** |
| 微信             | 不做：ClawBot 的图片是加密 CDN 对象，需要单独的解密流程；服务号需要认证账号。微信发来的图片只会作为一条“发来了一张图片，你看不到”的提示交给她，她会老实说看不到 | **未实现**                                     |

### 限制与处理

- 类型：JPEG / PNG / WebP / GIF（按**文件内容**判断，不信扩展名和 `Content-Type`），否则 415。
- 大小：原图最大 10 MB（413）；最多 4000 万像素（防解压炸弹）。
- 服务端用 sharp 处理：按 EXIF 旋转、最长边缩到 1280 px、统一存成 JPEG，**去掉全部元数据**（含 GPS）。
- 私有存储：放在 `artifactDir` 下，只有登录的主人能通过 `GET /api/companion/uploads/:id` 看到，匿名 401；
  数据库表 `companion_images`（迁移 `0024`）。**30 天**后文件由 worker 删除，只留一句文字描述。
  也可以在网页里删除（`DELETE /api/companion/uploads/:id`），文件和描述一并清掉。
- 发给模型：**只有当前这一轮**的图片原图会送给模型；之后的轮次，历史里只保留描述，
  所以她能说“刚才那张图的天空是蓝的”，但不会每轮都重复上传图片。
- 模型：沿用你在设置里选的聊天模型；需要支持图片输入（本机验证用的是 relay 的 `gemini-3.8-flash`，
  自定义模型要在 `pricing.custom` 里有价格才能用）。
- 看不了怎么办：识图调用失败时她会老实说“图片我这边看不到”，不会编。

### 人脸与证件：不进长期记忆

每张图在她回复前先做一次独立的“审看”调用（`SEE_PROMPT`），输出 `description` 和 `sensitive`：

- 有清晰人脸（自拍、合影、屏幕里的人）、身份证 / 护照 / 驾照 / 银行卡 / 工牌 / 车牌，**或拿不准**，一律 `sensitive = true`；
  输出读不懂也算 `sensitive`。倾向于保守。
- 描述里不允许写出证件号、手机号等文字，也不允许猜测人物身份。
- 对 `sensitive` 的那一轮（以及图片没看成的那一轮），长期记忆工具被收紧：
  `remember` 只能产生**候选卡**，必须你点“记住”才会保存；`update_memory` 直接拒绝。
  这不影响聊天本身：她仍然会自然地回应图片，只是不会自己把里面的内容存进记忆。
- 这是靠模型判断的**尽力而为**保护，不是 100 % 的：漏判时，最坏的结果也只是出现一张可以拒绝的候选卡，
  而不是静默保存。

## 2. 相似笔记确认卡（记忆去重第一步）

**不会自动合并。** 只提示，由你决定。

- 相似度：`lib/companion/similar.ts`，对归一化后的文字做**字符二元组 Dice 系数**（一条几乎完整包含在另一条里时也算相似），阈值 `0.6`（偏保守，宁可漏报）。
  同一条笔记的小改写（“冰美式咖啡” / “冰美式”）会被抓到，仅仅话题相同的不会。
- 什么时候出现：
  1. **你在“记忆”页添加**一条和已有笔记相似的话：笔记照常保存，同时生成一张建议卡；
  2. **她自己想记**一条相似的话：这条先不入库，变成建议卡（并在聊天里出现一张“这条和以前的很像”的卡）；
  3. 记忆页的“找相似的笔记”按钮：扫描现有笔记，为每一对生成建议卡。
- 卡上有两条原文、相似度和一个可以修改的“合并后的样子”（默认：一条包含另一条时取长的；否则取新的措辞，
  旧的写在卡上不会丢），三个按钮：
  - **合并**：保留较早的那条，文字换成合并后的样子，删掉较新的那条（她提议的那条候选则直接消失）；
  - **都留着**：两条都保留，这对以后不再提示；
  - **不要新的**：丢掉较新的那条（如果是她提议的，就不入库）。
- 数据：`memory_suggestions`（迁移 `0024`）。API：`GET /api/companion/memories/suggestions`，
  `POST /api/companion/memories/suggestions/:id`（`{action: "merge" | "keep" | "drop", mergedText?}`）。
- “重说”一条带建议卡的回复时，卡片一起被撤回，不会留下悬空的建议。

## 已知限制

- 微信发图未做；QQ 图片未在真机验证；Telegram 未用真 Bot 验证。
- 敏感判断依赖模型；动图（GIF）只取第一帧。
- 相似度是字符层面的，不懂同义改写（“住在上海” / “家在上海浦东”约 0.5，低于阈值，不会提示）。
  后续可以换成嵌入向量，但要先看真实数据里的误报率。

## 借鉴与致谢（概念，未复制代码）

- mem0（Apache-2.0）和 Letta / MemGPT（Apache-2.0）的“写入记忆前先检索相近条目，再决定新增 / 更新 / 忽略”的思路。
  这里的相似度算法和确认流程是自己写的；和它们不同的是：**不让模型自动合并，只出确认卡**。
