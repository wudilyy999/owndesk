## 当前标记的内容

截图新加的是**边框和引用编号**，没有把名称再画一遍。例如自绘测试图左上按钮原有文字 `Save`，新增的是棕色框与 `v10`。模型另收到结构化记录：

```json
{
  "source": "vision",
  "role": "candidate",
  "name": "Save",
  "bounds": { "x": 37, "y": 149, "width": 218, "height": 52 },
  "actions": ["click", "double_click"],
  "detector": "ocr+outline",
  "confidence": 0.8466053800000001,
  "ref": "v10"
}
```

原始字段保存在实验目录的 vision-marked.json 中。DOM 使用蓝色 `r`，AT-SPI 使用绿色 `a`，视觉使用棕色 `v`。编号每次观察重新分配，不能跨画面复用。

## 测量方法和范围

冻结当前开发工作站 `0.7.0 / guest6`，在新建的隔离容器中使用12个网页控件、12个 GTK 原生控件、20个 Canvas 自绘控件，共44个正样本，并布置静态文字、禁用/隐藏/遮挡等负样本。地面真值由测试程序直接记录布局与实际控件回调，独立于 DOM/AT-SPI/OCR 观察器。没有修改产品识别器或执行器，也没有迁移、重启或升级主预览。

**本轮测检测器和编号执行器。测试程序按真值几何选中编号，没有让云端模型自主判断按钮；云模型请求0，不能据此声称真实任务/任意软件有同样成功率。** Native 测试界面需要的 `gir1.2-gtk-3.0` 仅安装在实验容器，工作站镜像及部署依赖不变。

统计口径：

- **检出**：候选框中心落在真值可操作区域内。没有要求 OCR 框覆盖整个按钮；只框住按钮内文字也可能满足此条件。
- **名称正确**：大小写与连续空格归一化后，完整名称相同。漏检、空名、只读出部分文字都不算正确；无文字且未提供语义名的6个 Canvas 图标及1个 GTK 图标不进命名分母。
- **候选框精度**：场景区域内，框中心位于可操作控件的候选数/全部候选数。Canvas 排除浏览器工具栏，网页 DOM 排除系统装饰。
- **动作确认**：执行真实 guest 原动作链后，由测试界面实际事件回调确认目标。动作回执成功单独存储，不能取代目标回调。

### 原生动作的单项复核

首轮11次派发有10项产生预期回调。Zoom 数值框返回 AT-SPI `activate` 成功，测试最初监听的是物理 `button-press-event`，因此未记录目标回调。只对该项补做1次 `activate` 回调检查，收到 `zoom` 事件；原11次派发和未记录回调的结果均保留。当前测试夹具已改为监听正确的语义信号，产品执行器未改。

直接 guest 编号动作合计42次：首轮41次，加单项复核1次。41个不同的已检出目标获得动作确认；没有观察到点入另一个样本控件。图中3个视觉负候选未被自动点击。

## 实际暴露的缺口

1. **DOM 名称解析不完整**：当前依次读 aria-label、placeholder、name、textContent；没有完整处理关联 `<label>`、`aria-labelledby`、title。样本中的 Email address、Refresh data、Enable sync、Options 均有框且能操作，name 为空。
2. **原生控件语义覆盖不全**：Volume 滑块未进入 a 引用列表，当前视觉候选也没有补到它；Email address 未从关联标签恢复名称。标准按钮、复选框、切换按钮、输入框、数值框、组合框的相应样本可执行。
3. **视觉 OCR 缺乏功能语义**：放大镜为 Q，圆形图标为 ©，加号为“十”；检测出这些位置不表示知道其功能。
4. **视觉漏检**：纯三角播放图标、低对比度 Advanced 文字按钮没有框。小字 Apply filter 只有 Apply。
5. **视觉多余候选**：Report title、Status: ready、灰色 Disabled action 被框出。这些返回值本就标为 candidate，模型仍需判断可操作性。

这些结果支持优先补全语义名称解析与原生角色覆盖，再改进视觉候选分类。把全部 name 画到截图上会增加遮挡，并不能修复上述名称来源缺口。
