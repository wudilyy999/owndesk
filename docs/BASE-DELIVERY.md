## 1. 本轮范围

一个拥有者、一个主要助手、一个 Linux 桌面、一个 worker。复用已有实现：

1. 网页登录，在“模型与 Agent”配置自己的 API 与默认模型。
2. 用自然语言交办任务，浏览器 DOM、截图、键鼠、Shell 和文件工具共用同一工作站。
3. 网页看真实桌面；需要登录时接管，交还后重新观察并继续。
4. 任务完成后查看结果、下载成果；取消时真正停止工作站操作。
5. worker 重启后复用确定回执，未知模型请求/外部效果停下来等待复核。

暂缓团队配置、并行协作、更多交接分支、支付扩展、复杂例程和高级记忆。已有可选能力保留默认空交接名单，不再扩展，也不要求用户先学会这些功能。

## 3. 六项交付门槛

| 门槛         | 具体操作 / 通过标准                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------ |
| B1 安装      | 新独立库应用0015，拥有者可登录；Web/worker健康，版本和guest5配对                                 |
| B2 电脑操作  | 模型通过生产执行链打开网站、读取页面/截图、操作同一个浏览器                                      |
| B3 人机协作  | 桌面有实际画面；只读端不能控制；接管登录、交还后重新观察                                         |
| B4 成果      | 从网站下载一次报表，宿主检查字节/CSV，网页下载内容正确                                           |
| B5 中断/取消 | 人工等待时杀掉worker可恢复；实际Shell运行后取消，容器消失、心跳停止                              |
| B6 真实服务  | 用户配置的真实模型至少完成一次非敏感公网任务，记录调用、成本/未知费用与成果；普通公网DNS/TLS可用 |

`npm run test:delivery` 复用 `tests/deployment.ts basic-cua`：真实 Linux Docker、生产 Web/worker 镜像、HTTPS/WSS、真实桌面与浏览器；模型与报表网站受控。两项真实任务为一项报表完成、一项Shell取消，保留数量门槛。它验证B1—B5的受控机制，不验证B6。

测试需独立Linux引擎、已构建镜像和Playwright浏览器；可显式设置 `PA_LINUX_HOST_STATE` 与 `UI_BROWSER_PATH`。不能指向有用户数据的Docker主机。基础检查结束会停止专用VM并保留数据与原始日志，便于保留失败和复核；主服务不变。

本机网络已有fake-IP导致普通公网失败的证据。基础检查通过不改变该结论，也不降低保留地址阻断。B6使用直连网络或单独完成适配验收后继续。

## 4. 给用户的首个任务

配置完成后，在网页选择 OwnDesk Assistant，交办：

> 打开我给出的公开网页，提取页面标题和三个要点，保存为 page-summary.md 并提供下载。遇到登录先让我接管，等待我交还后继续。

核对网页真实内容与下载文件。随后在同一对话要求“把结果改成中文三条要点”，确认文件继续处理。先使用公开资料与非敏感账号；高风险识别仍部分依赖模型，暂不以付款或删重要文件作为首验。

用户已明确提供网关、两个模型并授权升级；密钥通过拥有者设置API加密保存。后续在本地设置页更新，模型与不限额验收授权不重复询问。
