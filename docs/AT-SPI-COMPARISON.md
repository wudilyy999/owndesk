# AT-SPI 优先与纯视觉：配对试验

日期：2026-10-30。状态：六个真实模型任务已结束，五个完整通过，一个达到预算后未完成收尾。未改动主实例。

## 实测结果

同一 `openai/gpt-6.1-terra` 接口、`owndesk-workstation:0.6.5`、1280×800 桌面、65,536 上下文窗口，每个 Task 最多48次模型请求。每个场景每组一次，无重跑、人工修正或追加预算。

| 场景            | 纯视觉                                                                            | AT-SPI 优先混合           | 混合组实际原生输入 / 鼠标键盘输入 |
| --------------- | --------------------------------------------------------------------------------- | ------------------------- | --------------------------------- |
| GTK 报告表单    | 通过；8请求；44.3秒                                                               | 通过；8请求；37.3秒       | 4 / 0                             |
| Thunar 文件整理 | 文件全部正确；48请求、265.5秒后预算暂停，停在父目录，未返回指定最终目录及报告完成 | 完整通过；48请求；303.9秒 | 13 / 21                           |
| XFCE 字体设置   | 通过；7请求；44.3秒                                                               | 通过；18请求；112.7秒     | 5 / 4                             |

请求包含摘要压缩。输入数只统计实际执行的原生 `press/focus/set_value` 和鼠标键盘，排除观察与 `complete_task`。原生派发记录均为 `dispatched`，独立业务验收另外进行；派发数不等于成功修改目标的次数。字体场景的5次原生输入包含重新打开对话框、重复填值及聚焦。

### 如何解读

- **原生操作确实生效。** 表单四个目标完全通过原生控件完成：标题变为 `Release checklist`、同步关闭、音量37→63、保存恰好一次。每步的新控件状态与最终 GTK 实际值一致，没有坐标或键盘回退。
- **复杂任务仍大量依赖视觉及快捷键。** 文件整理混合组有13次原生输入，同时需要11次坐标点击、10次快捷键。两组最终8个文件的路径及完整字节均正确，隐藏文件、旧版、草稿、原预算文件都保留；纯视觉未满足最终打开交付目录及完成任务的要求。不能把这个失败描述为文件误操作。
- **全局原生优先没有显示稳定的效率优势。** 字体场景两组均成功，混合组明显更慢、请求更多。三个案例的端到端结果为纯视觉2/3、混合3/3，核心表单/文件/字体状态均为3/3。这些数字只描述本轮样本，不充当统计成功率或对竞品的排名。

## 两个已定位的观察/执行缺口

### 1. 模型上下文裁剪丢失后部有效控件

Thunar 最终检查前的同一 observation，原回执有51个元素，模型实际请求只保留17个，`omittedElements=34`；后部的状态栏 `3 files: 114 bytes` 被裁掉。已按 observationId 对齐原回执与真实出站请求，排除了对错帧的误判。

字体场景中，原始窗口观察包含 Fonts 标签，模型却在后续请求中报告找不到该标签。长字体列表还会触发读取节点预算截断；这些问题需要区分“后端没有暴露”“读取预算截断”“上下文投影裁剪”，不能统一归因为应用不支持 AT-SPI。

当前 `projectObservation` 按遍历顺序保留元素，并同时携带扁平元素与树结构；前部侧栏、菜单和重复属性挤占预算。下一步应在原字数预算内精简字段、减少重复结构，并优先保留当前输入、选中项、状态栏与对话框确认控件。两张近期原图规则保持。

### 2. 双接口数值控件只改了文字，尚未提交数值

字体字号框同时提供 EditableText 和 Value。当前 `set_value` 优先调用 EditableText：两次原生回执都出现 `text="11"`、`value=10`。聚焦并按 Tab 后，下一份真实观察才变为 `text="11"`、`value=11`，最终系统配置通过。

这是明确的 setter 选择缺口。数值目标应优先调用可用的 Value 接口；文本目标走 EditableText，并继续检查实际业务值和提交状态。不能把 `effect=dispatched` 当作数值已经生效。原模型正确发现未生效并继续处理，但多次观察、重开对话框和提交动作带来了额外开销。

**上述两个缺口已记录，本轮未修改生产实现，未为修复重跑任何付费任务。** 优先做这两项小范围修复及零模型的原生控件定向验收，再决定默认路由强度；暂不引入新的调度框架。

## 原冻结方案（保留）

## 问题与边界

现有接口验收证明 AT-SPI 可读取和执行，历史真实模型样本仍主要使用坐标与键盘。本试验检查在相同任务下提供控件信息、原生工具与明确优先策略，是否改善实际执行。

使用当前生产 Task / worker / DBOS / 动作账本和工作站镜像，新增测试专用的 loopback 模型中继，改变发给模型的观察信息及策略。日常实例和产品默认行为保持。

## 冻结的试验设计

- 模型：`openai/gpt-6.1-terra`，相同服务、接口、输出限制和上下文窗口。
- 场景：GTK 报告表单、Thunar 文件整理、XFCE 字体设置。
- 两组：纯视觉；AT-SPI 优先混合。每个场景各执行一次，共六个独立 Task，每个最多48次模型请求。
- 每个单元使用新的 Agent / home 卷和相同软件、数据、窗口准备；交替两组先后顺序。无手册、记忆、人工修正和脚本捷径。
- 纯视觉组在模型传输边界移除控件树/控件属性及原生工具，保留原截图、窗口元信息、输入坐标与控制代。
- 混合组首先只能选择原生观察工具；获得控件观察后开放原生及视觉工具，提示模型优先使用可用原生动作。视觉回退须说明原因。
- 初次原生观察由实验工具列表约束；后续原生动作优先级仍由模型遵循提示。不会把“提供树”或“调用过一次原生工具”直接算作控件主导。

## 独立评分

表单读取 GTK 实际值与提交次数；文件任务核对全部文件字节、路径和保留项；字体任务核对系统配置及最终可见窗口。Agent 的完成声明不充当评分器。

记录任务是否完成且独立检查通过、请求/摘要数量、用时、输入/输出/缓存 token、费用未知项、原生工具和实际效果数量、坐标/键盘操作数量、原生拒绝与视觉回退原因。模型自行说明的回退原因单独标注，和驱动返回的无 Action / 歧义 / 不可用证据分开。

中继位于现有上下文组装之后。现有压缩阈值按原内部历史估算，对纯视觉组可能偏保守；两组固定相同窗口，分别记录是否实际触发压缩，发生时在结果中明确这一限制。最多两张有效截图及原控制安全链保持。

任何上游请求效果或费用未知时停止本批次，保留原 Task 和回执，使用原复核流程申请继续。工具拒绝和任务失败如实保留，不重新创建同一单元刷成功。没有模型价格时费用继续标为未知。

这是每场景一次的小样本探索，不作统计显著性、通用成功率或竞品排名结论。原始截图、轨迹、凭据及实验数据库仅保留在本机私有实验目录。
