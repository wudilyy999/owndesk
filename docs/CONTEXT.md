### 发现与修复

真实Terra跨软件任务的旧摘要把应用、目录、当前选项和操作结果反复描述为未知；字体对话框进入4次，已经达成目标仍持续重复核对。40次和80次预算正常触发暂停，原任务和所有回执保留。

对同一原始历史离线重建摘要请求，确认两个根因：

1. 摘要请求删除了当前目标与本Task用户补充，摘要模型不知道哪些要求需要持续跟踪。普通执行请求中原目标一直保留；缺失发生在摘要来源。
2. 来源先经过旧段600字符裁剪，再对SDK消息包装递归分预算，形成`tool-result → output → value → text`多层截断。模型只读到`ok=true`与裁剪标记，窗口名称和控件值已丢失。

当前实现复用原`planContextCompaction`与持久化checkpoint，完成以下根因修复：

- 摘要请求增加`currentTask`，带入原目标、完成合同及当前Task用户补充；普通执行侧继续逐字保留这些内容。
- 从完整原历史构造有界、内容感知的摘要来源，直接保留工具名、输入、结果与错误；压缩SDK包装前提取语义证据。
- 原生/网页观察保留窗口、应用、URL、页面文字，以及有界完整控件记录；优先保留文本、值、选中/聚焦/可编辑状态。网页只读叶文本、拒绝、错误和混合媒体描述也覆盖。
- 历史截图、opaque reasoning、旧控件操作句柄和几何坐标退出摘要观察；最近两轮闭合工具批次、当前最多两张有效图及原授权规则保持。
- 摘要明确维护当前状态、已确认进度、未核实项、下一未完成步骤；新局部观察缺少字段时保留此前已经观察到的事实，遇到相反新证据再修订。派发成功继续与效果确认区分。
- 沿用原`task_model_decisions.result.text / compaction.through`持久化、费用和恢复机制，没有新建状态框架、长期记忆表或每轮摘要器。旧checkpoint格式保持兼容。

实际例子：旧摘要只有“发生了复制和点击，应用与当前目录未知”；修复后的摘要能够记录“客户清单.csv已在目标目录被识别为36字节CSV，预算汇总.csv已被识别为39字节CSV；字体选择器重新打开后仍是11号；下一步返回交付目录做最终核对”。这些历史事实指导下一步，当前观察仍负责动作授权。

## 1. 成功标准与分层

- 各类工具返回首次进入模型时就受预算约束；完整原文留在原账本。
- 接近窗口时自动提炼旧历史，当前目标、完成合同、站立规则、本Task用户补充保留原文。
- 模型工作集、会话摘要、持久记忆与完整审计分层；缓存键和业务会话身份分别管理。
- 只在call/result闭合处切分旧段，保留的调用继续使用原ID。
- 压缩走原费用、月预算、取消、控制和未知请求复核链，恢复复用已保存响应。
- 摘要携带历史事实，动作授权仍由原宿主控制权、审批与成果检查决定。

## 3. 总窗口预算与自动触发

PA_CONTEXT_WINDOW_TOKENS默认65536，表示本安装为所用模型/网关配置的总窗口。该配置没有声称自动发现每个模型的真实上限。新Task在configSnapshot.contextWindowTokens冻结，旧Task缺字段时沿用本机配置。Ollama预算同时受现有16K/32K运行配置约束。

预算包括系统指令、记忆、工具JSON Schema、消息包装、工具参数/返回和reasoning元数据；当前图片预估8192 tokens，下一次输出预留8192 tokens。文本采用UTF-8字节数/3估算，并在同一压缩边界内用上次provider实际input用量向上校准。估算与精确tokenizer分开。

默认输入额度57344，软触发点为其80%，约45875预估tokens：

```text
原账本恢复完整history
 → 读取持久摘要边界，重建临时工作集
 → 工具投影 + provider适配 + schema预算
 → 达软阈值且有有效旧段：请求摘要
 → 保存摘要/用量/价格快照，返回原runtime重过预算与控制门
 → 摘要 + 原文规则/目标/合同/用户补充 + 最近完整批次
 → 原普通模型决定和动作链
```

软阈值保留余量；只有固定输入/近期内容时，窗口内可正常请求。硬额度超出且没有有效旧段时明确停止。每个普通决定前最多一次有效压缩，要求预估节省至少1024 tokens，并预留最大摘要空间，避免无收益循环。

例子：18轮文件读取和推理超过阈值，旧16轮提炼为“已读取report.csv；两次写入结果未知；下一步重新观察”，最近2个assistant轮次保持完整；当前“禁止发邮件”的补充逐字保留。原18轮回执仍在本地账本。

## 4. 摘要、恢复和异常

- 边界只落在完整工具批次之后，默认保留最近2个assistant轮次。
- 摘要输入包含上一摘要与新增旧段；旧图片和opaque reasoning从摘要来源移除，其他来源使用明确带标记的有界结构化摘录。
- 中文等UTF-8密集来源在本地继续缩小摘录，直到摘要请求自身符合预算；超出可处理规模会明确停止。
- 摘要最多12000字符，输出上限4096 tokens，禁用动作工具。
- 内容要求覆盖目标/限制、已确认结果、未知效果/失败、文件引用、记忆变更、决策与待办；区分模型描述和宿主证据。
- 原task_model_decisions.result保存text和compaction.through；边界引用完整history位置，journal不覆盖。
- 普通决定使用原正数decision_no，对应压缩使用负数，例如决定7前的压缩为-7。Task/thread/segment/toolCallId保持原身份。
- 原DBOS步骤恢复后，从原决定表读取摘要；不依赖进程缓存，不重新请求已保存响应。
- 摘要调用计入原maxSteps/费用/月预算。返回compacted后，runtime重过这些门槛和控制检查，才请求普通模型。

空白、过长、输出截断或含工具调用的摘要，保留成功响应及费用，明确拒绝使用，不伪造或自动重发。中断/失败保留unknown账本；负数决定也走原重试确认。序列化恢复后的模型错误继续关联实际失败的决定编号。

### 上游实际报超限

本地估算存在误差。400/413加明确context code/message会标记ContextWindowExceeded，费用继续按原策略保留未知并进入复核。按原复核链获准继续后，即使估算低于软阈值，也先压缩有效旧段，再请求普通模型；无有效旧段时要求校正窗口，避免原样重发。502、429、普通超时分别处理，不据此猜测拦截原因。

本次未继续或替换原Sol/Gemini的未决请求。冻结预算与模型窗口的修订需另行明确处理，不能通过抹去账本绕过未知费用。

## 5. 长期记忆与会话摘要

| 层                       | 当前机制                                                             |
| ------------------------ | -------------------------------------------------------------------- |
| 站立规则、目标、完成合同 | 每次重组保留原文，成果合同继续由宿主独立验证                         |
| 本Task工作集/摘要        | 执行段的事实和待办，按窗口自动压缩                                   |

| 持久memories             | 复用原memory_write/forget、事务和回放保护；新Task最多30条、12000字符 |

应用摘要时，程序还会从已提交memory工具结果重建独立变更覆盖层。删除标记/新保存值明确覆盖初始快照和旧摘要；摘要不会直接写入memories。原始审计仍包含历史值，删除持久便笺与清除审计分别处理。

本轮未新增自动画像写入、向量检索、文件式MEMORY.md、无限跨Task摘要或上下文用量UI，多Agent继续延期。
