# Companion · Stage B1：打字节奏、重说/编辑、可安装的网页应用

设计来源：`owndesk_stage_b_design.md` 的 B1。三件事都不改变“像真人聊天”的原则：
她不会一次把话全砸出来，你可以复制、让她换个说法，也可以把手机主屏当成一个 App 打开。

## 1. 打字节奏与“正在输入”

模型回复仍然**一次生成完**，只有“播放”被错开：

- 每个气泡先“打字”一会儿再出现：`0.4 s + 每字 0.06 s`，单条上限 3.5 s，±20 % 抖动；
  第一条上限 1.5 s（她在模型生成时已经“想”过了）；整段回复总长封顶约 8 s。
- 设置里的“打字节奏”：**自然**（默认）、**快**（`0.2 s + 每字 0.025 s`，单条上限 1.5 s，总长约 3.5 s）、
  **关闭**（一次全部显示，网页上文字边生成边显示，和以前一样）。
- 数据：`companions.typing_pace`；`companion_messages.reveal_at`（这个气泡什么时候算“已经发出”）。
  没到 `reveal_at` 的气泡在历史、列表、模型上下文里都看不到；用 `reveal_at` 而不是改写
  `created_at`，是为了不让消息顺序和“最近一轮”的判断依赖未来时间。
- 纯函数在 `lib/companion/pacing.ts`（随机数、睡眠都可注入，测试不用真等）。

### 网页

SSE 新增 `typing` 事件；`messages` 事件按时序逐个气泡推送。界面显示三个点的“正在输入”，
每个气泡到点才出现。关掉页面也没事：气泡已经落库，到点后刷新就能看到。

### 渠道（Telegram / QQ / 微信）

后续气泡写入 `channel_outbox.notBefore`；处理这条消息的进程按时序等待并发送，
进程中途挂掉由 worker 每 2 秒的 tick 补发（`deliverOutbox` 在进程内串行，不会重复发）。
“正在输入”各平台能力不同：

| 渠道         | 做法                                                                                   | 状态                                                                         |
| ------------ | -------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Telegram     | `sendChatAction: typing`（约 5 秒或发消息即清除），在模型生成前和每次等待前各发一次    | 已实现；用假 Bot API 验证了请求，**未用真 Bot 验证**                         |
| 微信 ClawBot | `getconfig` 取 `typing_ticket` → `sendtyping`（status 1 = 输入中，最后 status 2 取消） | 已实现；协议来自腾讯 openclaw-weixin 文档，**未用真账号验证**                |
| QQ           | C2C `msg_type=6` + `input_notify`（最长 60 s），带 `msg_id` + `msg_seq`                | **默认关闭**（设置项 `qq.typingNotify`，环境变量 `QQ_TYPING_NOTIFY=1` 开启） |
| 微信服务号   | `custom/typing` 需要已认证账号且 30 秒内有互动                                         | 不做；只有延迟                                                               |

**QQ 为什么默认关闭**：被动回复每条消息最多 4 次（`msg_seq` 1–4），而官方文档没有写
`msg_type=6` 是否占用其中一次。我们的做法是：开启后每条消息只发一次 typing，占用一个 `msg_seq`，
正文自动少一个名额（超出的气泡会合并进最后一条，和原有规则一致）。**没有真实 QQ 机器人凭据，无法验证**，
所以只验证了我们这一侧的请求形状和 seq 计数（测试里用假 QQ 服务）。想试的人：在真机上打开开关，
发一条消息，看是否收到 4 条以内的正文；不通就关掉，节奏仍然有效，只是没有“正在输入”。

## 2. 复制、重说、编辑上一条（仅网页）

- 每个文字气泡有“复制”（HTTP 环境下也可用）。
- 最后一轮她的回复多一个“重说”；你自己的最后一条消息多一个“编辑”（改完“保存并重发”）。
- **只允许最近一轮**，且必须是网页里的 `chat` 消息：她后来又发了别的（别的渠道的消息、已经处理过的确认卡）就不能再改，
  服务器返回 409 并说明原因，历史不会被改乱。
- 重说 = 把上一轮她的气泡标记 `superseded_at`（保留，界面和模型上下文里隐藏），用同一条用户消息重新生成；
  编辑 = 同样隐藏旧的用户消息和回复，写入新的用户消息。每轮最多重说 3 次（`metadata.redo`）。
- **重说时记忆只读**：`remember` / `update_memory` / `forget` 在这一次不生效（模型会被告知“这次不改记忆”），
  所以不会“重来一次记两遍”。她那一轮提出的“记忆候选”卡和对应的候选记忆在新回复成功后一并作废。
  编辑不是只读（相当于你说了一句新话）。
- **失败不丢东西**：模型出错、超额度等，旧回复原样恢复；编辑失败还会删掉刚写的新用户消息。
- 费用照常记账。危机用语（编辑成危机内容）走原来的固定回复，不会被重说成别的。

## 3. 可安装（PWA）

- `app/manifest.ts`：`display: standalone`，起始页 `/companion`，192/512 图标和一个 maskable 图标；
  `public/icons/apple-touch-icon.png` + `appleWebApp` 元数据给 iOS。
- `public/sw.js`：只做两件事——让应用满足“可安装”，以及页面加载失败时显示 `public/offline.html`。
  **不缓存任何页面、接口返回或聊天内容**（它们是私密的）。
- 图标由 `scripts/generate-pwa-icons.mjs`（纯 node，无依赖）画出；`npm run pwa:icons` 可重新生成。
- 不含推送（属于 B2）。
