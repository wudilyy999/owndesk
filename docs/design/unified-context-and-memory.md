# OwnDesk 统一上下文与长期记忆设计

状态：提案，待审阅。2026-11-20；OwnDesk 基线 `7024cad`。本文描述下一步怎么改，已上线的行为见 [CONTEXT.md](../CONTEXT.md)。

## 1. 主人实际会体验到什么

对话短时直接读原文，不调用摘要模型。每次追加先限制新工具回执的长度、折叠可确认无用的旧工具正文。这样处理后仍装不下下一次请求时，才把较早的一段对话压成摘要；最近几轮逐字留下，后续继续追加。第二次压缩只读「上次摘要 + 这次移出近期区的原文」。原始聊天、任务记录和文件仍留在各自的位置，可按引用重读。

例如，第一轮约定「发票按开票日归档」，第 40 轮改成「从现在起按付款日」。即使第一轮已经压缩，模型也能看到旧约定和最近的更正；下一次摘要应写明旧规则已经被替代。随后从聊天确认跑腿，任务拿到**提议当时**的规则；再把任务交给另一个 Agent，它也拿到适用于这项工作的规则。无关 Agent 打开的新聊天不会看到这段历史。

设计依据是两个可复查的源码版本：[Codex 压缩实现（cf881a6）](https://github.com/openai/codex/blob/cf881a627dd52e7aecef63416c1acd2a89c4dfbd/codex-rs/core/src/compact.rs)把压缩结果作为检查点重组会话；[OpenCode 会话压缩（56dc95b）](https://github.com/sst/opencode/blob/56dc95bff5f002321a12de5bbbe2783cd0c87e2a/packages/core/src/session/compaction.ts)记录从哪里开始保留原文，并为下一次输出留空间。OwnDesk 借鉴这两点；以下预算、权限和恢复细节由 OwnDesk 自己定义。

## 2. 一次模型请求怎样组装

| 组成         | 内容                                                                   | 超长时怎样处理                                                                   |
| ------------ | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 每次必带     | 当前指令、主人的当前请求与有效更正、任务目标与完成条件、能力和预算约束 | 从可信记录重建，保留原文。当前授权及动作是否成功，由原审批和动作账本判定         |
| 较早历史     | 旧约定、已验证的结果、已被替代的结论、文件和证据引用、未完成事项       | 一份滚动摘要，每条关键事实带来源轮次或事件 ID；没有依据的字段留空                |
| 近期交互     | 摘要边界之后的用户与助手文本，以及配对的工具调用和结果                 | 文本逐字追加。工具沿用已有的有界输出和图片投影；大文件、截图保留可回读的引用     |
| 相关长期记忆 | 当前 Agent 的有效偏好、事实及主题，按这次任务所需读取                  | 给定预算内带主题和相关笔记；更多细节按主题或页码读取。候选和已删除条目不参与读取 |

会话摘要只供这个会话及显式交接使用，不能自动写成永久偏好。长期记忆保留现有查看、编辑、删除、撤销和候选确认体验。确定性工作流继续从步骤检查点执行，不为它增加模型调用；一次识图、一条记忆更新等短调用只共用预算计算，不建立虚构的会话历史。

### 三步处理：截断单条 → 折叠旧结果 → 必要时才摘要

**上游依据。** [OpenCode 的输出截断器（56dc95b）](https://github.com/sst/opencode/blob/56dc95bff5f002321a12de5bbbe2783cd0c87e2a/packages/core/src/tool-output.ts)分别检查行数和字节数，默认 2,000 行、50 KiB，超限返回预览和可分段读取的文件；[OpenCode v1.2.10 的会话实现](https://github.com/anomalyco/opencode/blob/v1.2.10/packages/opencode/src/session/compaction.ts)将旧工具清理 `prune` 与会话摘要分开，向前扫描已完成的工具结果，保护近期和特定工具，达到可回收量才标记。[Codex 配置参考](https://developers.openai.com/codex/config-reference/)也分别提供单条工具输出预算 `tool_output_token_limit` 和整段历史阈值 `model_auto_compact_token_limit`。这些是借鉴点；下面的折叠条件与触发顺序是 OwnDesk 的选择。

1. **新结果到达时截断单条，不调用模型。** 在供应商序列化前，对每次调用的全部结果合计限长，包括文本、结构化字段和媒体。短结果原样给模型；长日志给退出码、可定位的错误行和尾部，文件或表格给范围及截取标记，截图沿用已有媒体预算。先保存允许保留的原回执，返回同一任务内可分段读取的 `resultRef`；读取时检查作用域并限制每页大小。尚未写入、已过期或工具本来就未捕获的内容要明确标出，不能承诺可回读。单条上限独立于会话是否已满。
2. **每次追加后、下次请求前，折叠确定无用的旧正文，不调用模型。** 只改模型将收到的消息视图，不动原回执。按确定性规则判断：同一文件同一版本同一区间被再次读取、同一页面的旧观察被新观察取代、已结束且已有结构化结论的重复日志，均可留下短回执：`调用 ID / 工具与对象 / 状态或退出码 / 关键结果 / 原记录引用`。仍保留每个调用对应的工具结果及次序。最新有效观察、尚在使用的数据、未解决的错误、待确认或效果未知的动作、写入回执的关键字段、独立验收所需证据均受保护；不能证明旧正文无用时保留。折叠已经发生的历史保持稳定，重启重建同一视图；需看细节就按引用重读，不重跑原动作。
3. **折叠后仍装不下才生成会话摘要。** 设模型窗口为 `W`，本次输出预留为 `R`，有效输入预算 `B = min(W − R, 服务商单独声明的输入上限)`（未声明时取 `W − R`）。投影后的输入估算 `I` 包含系统提示、工具定义、消息包装、媒体、记忆、现有摘要和原文；同模型的历史实测输入可用来校准。若 `I ≤ B` 则直接请求，摘要调用数必须为零；不按 80%、轮数、闲置时间或后台定时启动摘要。若 `I > B` 且有可折叠的旧对话，摘要调用只读「上次摘要 + 将移出近期区的连续原文及工具短回执」。近期区目标为 `min(15,000 token, 可分给历史的预算 × 30%)`，仅用于选择切点。保留当前请求、有效更正和最近完整轮次，不拆工具批次；验证摘要完整、引用有效并实际省空间后才前移游标。

估算有误且上游明确拒绝上下文过长时，将该拒绝视为超预算：重新组装，优先折叠，在必要时压缩一次，再重试一次。已输出内容、已执行或效果未知的动作不重放。若仅必带材料就装不下，直接说明哪项输入过大；若摘要失败则保留原记录与游标。摘要走原有费用账本；前两步不消耗模型调用。

**工具例子：** 第一次读文件 A 的 1–200 行，给模型这段原文。随后重读相同版本的同一区间，前一条可替换为「已读 A:1–200，内容同回执 19，见回执 12」，新一条保留正文。此时完整请求能放下，聊天消息一字不改，摘要调用为零。若是两个版本在做差异分析，则两份内容都仍有用途，不能按文件名折叠。

**例：** 第一次选到第 48 轮为止，则下次看「摘要 1–48 + 第 49 轮到当前轮的原文」。第 65、66 轮进来只追加。下次若选到第 60 轮，就用「原摘要 + 第 49–60 轮」得到新摘要，继续保留第 61 轮以后的原文。切点由实际内容长度决定。

### 电脑操作：把两张截图当作对照，不当作两套可用坐标

- 本次模型请求最多带当前控制会话的两张桌面截图，按真实图片数量计数。前一张用于比较菜单是否打开、文件是否出现；输入只用最新有效观察。人工接管或工作站重启后，用控制代次与启动 ID 排除旧图。持久化回执和验收截图沿用原有保留策略。
- 最新观察可能只有 DOM 或 AT-SPI 控件树。这时旧图仍是历史，坐标操作须重新截屏；可访问性工具只用当前观察的引用。窗口、页面、缩放和控件变化后先获取新观察，摘要只记窗口、目标、语义状态和待验证事项。
- 读取同一视图得到可证明相同的完整控件树时，旧回执可引用新树。部分树、未知效果、错误和输入回执分别保留；截图前后看起来一样不能证明一次操作失败，也不构成重试依据。

## 4. 长期记忆如何写入和忘记

**写入。** 主人说「我现在改喝红茶」时，先按主题名、事实文本和已有归类找候选；主题匹配不足时分页查找。命中旧条目就按 ID 更新并同步主题；确实新出现的事实才新增。默认用现有数据库查询，无需向量库。一次预算内无法确认重复或冲突时，保留待确认候选，不凭部分匹配删除、合并或覆盖其他事实。分页整理先产出引用真实笔记 ID 的操作，再按读到的版本提交；并发编辑冲突时重读。

**遗忘。** 删除或纠正记忆时记录变更版本；装配请求时先应用当前有效值，旧摘要若引用受影响的笔记或旧版本，就作废相关部分并从允许的材料重建。无法判断影响范围的旧格式摘要整份失效，在重建成功前不得注入。用户要求忘记的旧值也须从将发给模型的旧聊天、冻结快照及再次摘要的输入中遮去；界面原始对话和审计记录保留。包含旧摘要的进行中请求可能已经发给服务商，此规则从下一次组装开始生效。撤销删除以记忆变更记录为准。

## 5. 如何存、如何恢复、如何回退

第一版抽出一个共用的预算与切分函数，和一个按游标装配模型输入的函数。业务调用方只提供作用域、必带内容、按时间读取的交互、摘要模板与所属账本。聊天和任务保持各自的摘要风格，统一覆盖关系和失败语义。复用 `lib/agent/context.ts` 的工具投影和 `lib/companion/context.ts` 的检查点经验，不另起一个后台记忆服务。

检查点最少记录 `格式版本、作用域、已覆盖到的稳定游标、摘要及来源、记忆变更版本`。消息用稳定的时间和 ID 排序；线程用轮号，目标用已结束的轮号，任务和实验室用执行段及步骤序号。在指定历史上界读取；同一输入版本的检查点以条件写入，迟到结果不能覆盖较新的结果。重说或编辑命中已覆盖区间时，从受影响点前重建。只有连续、可读取的区间才可标记为已摘要。

**存储选择。** 聊天沿用现有设置键；任务沿用决定和尝试账本；线程和目标首版只需各自一份带版本的检查点，可使用独立命名的设置键，并随实体删除清理。实验室目前的消息数组在内存中，需要先在受信的实验目录保存按步骤追加的脱敏工具回执、工件引用和候选版本，再保存切点。工具未收到回执时，先核对候选工作树或评审证据；不能确认就停在当前步。摘要不证明文件已写入或测试已通过。

**升级与回退。** 新格式使用独立键或兼容的附加字段。首次访问时读取现有检查点和原记录按需升级，避免启动时重写全部历史；已有不可恢复的区间标为缺失。镜像回退后旧版继续读取原格式，任务、文件、笔记和审批仍由原表或卷保存。再次升级时重新校验历史边界和记忆版本，尤其不能恢复回退期间被删除的事实。首版不引入新依赖或破坏性迁移。

## 6. 实施顺序与验收

| 顺序 | 可独立交付的改动                                   | 怎样判定完成                                                                                                                               |
| ---- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 1    | 抽出共用切分器，先接聊天与任务；随即接改造者和评审 | 用小模型窗口强制连续压缩两次，核对旧约定、近期逐字文本、工具配对；实验室中途重启，从已确认步骤恢复，未知效果不重做，评审能找回自己的证据   |
| 2    | 接线程、长期目标及交接                             | 用超过 200 个任务的线程和超过 8 轮的目标，找回首轮约束和最近更正；延迟确认旧跑腿卡不会读到未来消息；另一个 Agent 只收到这次交接的资料      |
| 3    | 接长期记忆读写整理、生活时段和短调用；验证升级回退 | 记忆量超过窗口仍能找到较早事实并纠正；删除后检查实际发给模型的输入，确认旧值不再出现；候选读不到主人真实历史，旧镜像可继续原任务且文件保留 |

第一阶段另测三个边界：单条巨型输出只产生预览且能按范围回读；原请求超限、折叠后刚好等于预算时摘要调用为零；折叠后仍超预算才调用摘要，近期用户原文与错误证据仍在。以发送给模型的实际载荷为准，界面收起日志不算通过。

每阶段先用合成记录断言**实际发给模型的消息、持久化边界和调用次数**。真实模型只验证受控模型回答不了的问题：它能否在经历两次压缩后，根据早期约束和后来的改口办对一件事。记录输入 token、摘要次数和费用，正常追加的短轮次应为零次摘要。以上是实施时的验收标准，本稿不改变运行行为。
