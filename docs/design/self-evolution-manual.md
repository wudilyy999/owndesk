# 使用手册：长期目标与自我改进（草案）

> 这份手册对应设计稿 [goal-and-self-evolution-plan.md](./goal-and-self-evolution-plan.md)。每一节标了它属于哪个阶段，**【A1】是第一个开发的阶段，其余都还没做**：
>
> - **【A1】【B0】【B1】**：第一批要做的
> - **【A2】【B2】【B3】【B4】**：以后的阶段
>
> 文中的按钮名、默认数字都是暂定的，开发时以实际界面为准。

---

## 一、长期目标

### 1. 什么时候用

一次办不完、需要她反复推进、而且"做成什么样"说得清楚的事。比如：

- "把我收藏的 30 篇文章都读完，每篇写一段摘要，汇总成一个表格"
- "每天看一次这 5 个商品的价格，降到 300 以下的告诉我，直到月底"（按计划推进，【A2】）
- "把我的旧照片按年份整理进文件夹"

一次就能办完的事，直接让她"去办"就行，不用开目标。

### 2. 怎么设置【A1】

**方法一：在聊天里说**

> 帮我定个目标：把收藏夹里的 30 篇文章都读完，每篇写 100 字摘要，放进一个表格，做完算完成。预算 1 美元以内，一周内。

她会回一张**目标卡**，上面写着：

- **目标**：她理解的版本
- **怎么算完成**：例如"表格里有 30 行，每行都有标题、链接、摘要"
- **上限（可选）**：最多花多少钱、最多多少轮、截止日期。**不填就不限**，只受每月总预算约束
- **节奏**：做完一轮接着做下一轮（"按计划"，例如每天 9 点一轮，属于【A2】）

觉得不对就告诉她哪里要改，她会重新出一张卡；点卡上的"确认，开始"后才会开始。**只在聊天里回"好"不算确认**，这和现在的"办事卡"规则一样。

**方法二：在网页的"目标"页点"新建目标"**，填同样的内容。CSV 表格这类**文件完成条件**目前只能在这里设置。

**写好完成条件的小技巧**：尽量写"看得见、能检查"的结果，比如"表格有 30 行""文件夹里每个年份一个子文件夹"。如果完成条件能对应到一个文件（例如 CSV 表格），系统会**自动检查**是否达标；如果不能，建议勾上"完成时需要我确认"。

### 3. 进行中你会看到什么【A1】

- **长期目标页**（工作现场左侧的"长期目标"，地址 `/objectives`）：当前状态、第几轮、每轮做了什么（一两句话）、用了多少步、已花费（设了上限的话也显示上限）、截止时间；每一轮都能点"查看任务"看详细过程。
- **聊天里**：目标交给她（伴侣）做时，每轮结束会有一条简短进度，例如"第 3 轮：又读完 8 篇，现在 19/30"。如果某一轮卡住了（比如某个网站要登录），这一轮的任务里会出现请你处理的卡，你处理之后她接着做；在那之前不会开新的一轮。
- **完成时**：她认为整个目标做完了，会报告"已完成"，然后：
  - 设了文件完成条件（例如"CSV 表格至少 10 行，含这些列"）：系统**自动检查**，通过才算完成；不通过就退回去让她接着改。
  - 勾了"完成时需要我确认"：你会在任务里看到审核卡，附成果文件。你确认才算完成。
  - 两样都没设：按她的报告直接算完成。所以重要的目标，建议至少设一项。

### 4. 暂停、继续、停止【A1】

| 操作 | 怎么做                                       | 效果                                           |
| ---- | -------------------------------------------- | ---------------------------------------------- |
| 暂停 | 目标页的"暂停"，或在聊天里说"先暂停那个目标" | 正在做的这一轮做完就停，不再开新的一轮         |
| 继续 | 目标页的"继续"（需要点按钮确认）             | 从下一轮接着做，进度不丢                       |
| 停止 | 目标页的"停止"，或在聊天里说"那个目标不做了" | 正在做的这一轮立即取消，目标结束，已有成果保留 |

机器重启或更新后，进行中的目标会从断点接着做，不会重复做已经做完的轮次。

### 5. 上限和花费【A1】

- 目标**默认不设任何上限**，会一直推进到完成，或者你暂停、停止。
- 你可以给目标设：最多花多少钱、最多多少步、最多多少轮、截止时间。设了哪项，哪项才生效；任一项到了，目标就停在"已达上限"，每轮的进度记录都保留着。提高或去掉上限后点"继续"，会接着做。
- **每轮步数**（默认 40，和普通办事一样）只决定一轮做多少。一轮的步数用完，这一轮就结束，下一轮接着做，不会弹卡打扰你。
- **月预算照常生效**：目标花的钱算在每月总预算里。月预算用完时，目标也会停下等你，不能绕过。
- 连续 3 轮都出错（比如网站一直打不开），目标会自动暂停，并写明原因。

## 二、自我改进（"初号机"）

### 1. 这是什么

你可以让她**改进自己**：加一个功能、改一个行为、调一个界面。这个过程：

1. 在一个**隔离的实验室**里复制出一份"候选版本"；
2. 由"改造者"修改候选，你现在用的版本完全不受影响；
3. 系统自动跑**全套测试和真实实测**，候选改不了这些测试；
4. 全部通过后给你一份**报告**；
5. 你点"采用"才换成新版本。**旧版本一直保留，可以一键回退**；新版本一旦不健康，会**自动回退**。

不需要懂代码，也不需要 GitHub 账号。所有事情都在你自己的机器上完成。

这个功能默认关闭，需要在"设置 → 自我改进"里打开。【B1】

### 2. 怎么提改进【B1】

直接在聊天里说你想要什么。像跟人提需求一样说清楚"现在怎样、希望怎样"就行：

> 晚上 11 点到早上 8 点别给我推送，有消息攒着，早上 8 点一起发给我。

> 日记页能不能加个按日期搜索？我想找上个月的日记。

**她会先判断要不要改代码。** 很多需求不用改代码就能实现，她会直接帮你办好，不进实验室，更快也更省钱：

| 你说的                     | 她会怎么做                    |
| -------------------------- | ----------------------------- |
| "说话别那么正式"           | 改人设设置                    |
| "记住我不吃香菜"           | 记进记忆                      |
| "每周一提醒我交周报"       | 建一个定时任务                |
| "以后订外卖都按这个步骤来" | 存成操作手册                  |
| "日记页加个搜索框"         | **需要改代码 → 发改进提议卡** |

**改进提议卡**上会写：

- **要改什么**：她用大白话复述的需求
- **验收清单**：做完后会实际检查的几件事，例如：
  - ☐ 日记页顶部有日期选择
  - ☐ 选"上个月"只显示上个月的日记
  - ☐ 没有日记的日期显示"这天没有日记"
- **上限（可选）**：最多几轮、多长时间、多少钱。**不填就不限**，只受每月总预算约束
- **范围说明**：第一版能改哪些、不能改哪些（见第 7 节）

**验收清单很重要**，系统就是按它来实测的。觉得少了什么，直接在卡上加；确认后才开始。

### 3. 进行中你会看到什么【B1】

改进本质上是一个特殊的长期目标，所以在"目标"页能看到，也能**暂停 / 继续 / 停止**，用法和上面一样。聊天里会有简短进度：

> 实验室：第 1 版改好了，正在跑测试…
>
> 实验室：第 1 版有 2 项测试没过（日期为空时报错），正在改第 2 版…
>
> 实验室：第 2 版全部通过，报告已经准备好。

改进进行期间，你照常跟她聊天、让她办事都不受影响。机器资源紧张时（默认 4 核 8G），她自己的"上网、记录生活"会暂时少一些。

### 4. 怎么审阅【B1】

全部通过后，你会收到一张**改进报告卡**：

- **改了什么**：大白话说明，附前后对比截图
- **验收清单**：每一项 ✅，附实测截图。这些是由一个**独立的检查员**在候选版本上实际操作得到的，不是改造者自己说的
- **测试结果**：例如"自动测试 204/204，真实实测 36/36"
- **花费**：这次改进实际花了多少
- **技术细节**（默认折叠）：改了哪些文件，想看可以展开看具体改动

卡上的按钮：

| 按钮           | 作用                                                                           |
| -------------- | ------------------------------------------------------------------------------ |
| **试用**【B2】 | 在网页里打开候选版本亲手点点看。用的是合成的测试数据，你采用、放弃或关掉时停止 |
| **采用**       | 换成新版本（见第 5 节）                                                        |
| **再改改**     | 写下哪里不满意，她接着改下一版，测试会重新全部跑一遍                           |
| **放弃**       | 不要这个改进。候选会留在档案里，以后可以再拿出来接着改                         |

只要有任何一项测试没过，就**不会出现"采用"按钮**。她会自动接着改；你设了上限并且用完了还没过，就停下来告诉你卡在哪里。

### 5. 采用和出问题时的自动回退【B0 / B1】

点"采用"后：

1. 系统先给当前数据做一次快照，再换成新版本。中间大约有一两分钟连不上，跟平时升级一样。
2. 系统会持续检查网页、后台和聊天是否正常。没有固定的"观察期"，什么时候发现问题都一样处理。
3. 一旦发现新版本有问题，会**先自动换回旧版本**，保证你能照常用，然后告诉你出了什么问题。你的数据不受影响。
4. 接着她会**在副本里 debug**：拿故障信息复现、修好，再把全部测试重新跑一遍。都通过后你会收到新的报告卡，再决定要不要采用。

### 6. 版本和回退【B0】

"设置 → 版本"页能看到：

- **当前版本**：例如 `local-3`（基于官方 v0.18.0）
- **保留的版本**：上一个版本和最近一个官方版本，默认保留 3 个，可以一键切换
- **历史**：每个版本是从哪个版本改来的、对应哪条需求、测试结果、花费、什么时候采用的；被放弃的候选也在这里（谱系树页面属于【B3】）

**一键回退**：在版本页选一个保留的版本，点"切换到这个版本"。流程和采用一样，也会做健康检测。第一阶段的改进不会改数据库结构，所以回退后数据完全正常。

### 7. 第一版的限制【B1】

为了让第一版**安全、回退干净**，候选版本暂时**不能**：

- 改测试本身、改评测和检查流程、改预算 / 登录 / 密码库 / 网络防护相关的部分。这些只会随官方版本更新；
- 加新的第三方软件包；
- 改数据库结构。追加式改动属于【B2】；
- 改"她的电脑"（工作站）和浏览器控制相关的代码。属于【B2】。

改动触及这些地方时，候选会被自动退回，她会告诉你"这个需求要等下一阶段才能做"，或者换一种不碰这些地方的做法。

其他限制：

- **同一时间只跑一个改进**，后提的会排队；
- 默认机器是 4 核 8G，一次改进大约要几十分钟到两小时（第一阶段实测后更新这个数字）；构建期间机器会比较忙；
- 候选版本里**没有你的任何密码、密钥、登录状态，也没有你的真实聊天和记忆**，只有人设、设置和合成的测试聊天与记忆；它也**不能上网**，只能通过本体的受限通道调用模型，花费计入这个改进和月预算；
- 改造者也可能理解错你的意思。所以验收清单要写清楚，报告也请看一眼再采用。

### 8. 官方出新版本时【B3】

如果你有本地改进，版本页会提示：

> 官方有新版本 v0.19.0。你有 3 个本地改进。

- **合并升级（推荐）**：她在实验室里把你的改进叠到新官方版本上。有冲突的话她会尝试解决；某个改进官方已经做了，就自动丢掉。然后**同样跑全套测试**，通过后由你采用。
- **只用官方版本**：放弃本地改进，直接升级。你提过的需求文字会保留，以后可以重新提。

直接在命令行跑 `scripts/upgrade.sh` 时，如果有本地改进，脚本会先提醒你，避免误覆盖。

### 9. 分享改进【B4，以后】

可以把一个改进导出成"改进包"发给别人。对方导入后，会在他自己的机器上**重新跑一遍全部测试**，通过了才能采用。默认关闭。

## 三、常见问题

**问：改进会不会把她"改坏"？**
答：会有三道关：采用前必须全部测试通过；采用后一旦发现问题就先自动回退，再在副本里修好重测；之后任何时候都可以一键回到旧版本。

**问：她能不能偷偷改掉测试，让自己"通过"？**
答：不能。测试和检查流程来自你**当前正在用的版本**，候选改不了；改了相关文件会被直接退回。"通过"只认系统自己跑出来的结果，不认改造者的说法。

**问：会不会乱花钱？**
答：默认不设上限，但每个改进和每个目标都可以设自己的上限；月预算始终生效，到了就停下来等你。目标页和报告卡上都能看到已经花了多少。

**问：我的隐私会进实验室吗？**
答：不会。密码、密钥、登录状态、聊天渠道凭证、真实聊天和记忆一律不进，实验室里只有人设、设置和合成的测试数据。所有东西都在你自己的机器上。
