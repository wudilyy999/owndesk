# 资源测量与空闲工作站（P7）

当前证据：`capacity-baseline.json` 的 8 任务短程测量与 `idle-workstations.json` 的 9 任务空闲停机/唤醒均已通过。普通公网 DNS、实际 VPS、长期容量和整体 上游项目 对照仍单独验收。主服务继续运行 0.8.1-dev，本文件不构成升级主服务或开放公网的放行。

## 1. 已测的机器与任务

- 专用 Linux ARM VM，2 vCPU，Docker 报告可用内存 3,040,575,488 字节；配置内存 3 GiB。
- 工作站限制 1 CPU / 1,536 MiB；只读 viewer 限制 0.5 CPU / 256 MiB。
- 生产 PostgreSQL、Web、worker、Caddy，独立初始化、拥有者 API、真实有界面 Chromium 与文件提取。
- 同一个 Agent 连续 8 次：打开受控站点、DOM 观察、下载 CSV、读取/另存、桌面 Ctrl+W 关闭报表页、宿主校验交付。每份 4 行、合计 620，8 次下载、56 次受控模型请求，结束后只剩一个空白页；最后检查 guest/viewer 的 OOMKilled=false。
- 模型服务固定返回工具决定，每次人为等待 500 ms；网站在测试环境跳过登录。此实验衡量执行与存储消耗，不衡量真实模型理解、真实登录、网站适应能力或网络推理速度。
- API 客户端临时忽略本地测试 CA 错误；本实验没有重新验收 TLS。CA 验证的 HTTPS/WSS 记录由先前部署/恢复实验承担。

原始目录：`data/experiments/pa-linux-1792903976167/attempt-1792906944635`。完整样本在 resource-samples.json，逐任务成果在 task-results.json。总时长约 175 秒，包含安装、采样与最后 30 秒等待。

## 3. 空闲停机策略

短程数据支持优先释放已完成任务的桌面，保留当前单 worker 与现有容器模型。候选复用 上游项目 的 15 分钟默认值和“停止后保留 home”生命周期，由受信 worker 核对业务状态。

`WORKSTATION_IDLE_MINUTES` 取整数 0—1440，默认 15；0 禁用。部署生成器写入默认值，Compose 只传给 worker。修改后按排空/备份/更新配套镜像的流程重启 worker；当前没有对应的拥有者网页开关。

worker 每约 30 秒检查一次，同时满足以下条件才尝试停止：

1. workstation_control 为 idle，未占用 Task，没有待交接决定，最后更新时间超过阈值。
2. 当前 Agent 没有 queued/running/waiting_user/needs_review 等未终止任务。
3. 取得原工作站生命周期锁后，再核对前两项，保护任务提交与准备之间的窗口。

按顺序停止 viewer 和 guest，确认实际不再运行后，递增 epoch、清除 bootId。容器、home/profile、系统层和成果均不删除；在内存中的页面引用与旧控制权限不能继续使用。下一条任务通过现有 ensure/acquire 路径唤醒和取得新控制。

等待登录、未知提交、未知计费、排队或人工决定的任务保留现场；它们仍可能长期占资源。拥有者可通过原任务界面核对、继续或实际取消。定时器不擅自将等待改成完成，也不自动重发外部请求。

空闲维护使用独立异步维护循环和已有生命周期锁，业务执行仍只有原 DBOS worker。停止失败明确报错并触发既有 fail-stop，不登记成成功停机。guest 自带 idle watcher 继续设为 0，避免它在模型等待或人类操作期间自行决定停机。

## 4. 定向验收入口

```sh
npm run test:capacity
npm run test:capacity:idle
```

两个入口目前使用保留的专用 Colima Linux VM：PA_LINUX_HOST_STATE 指向该实验引擎，PA_CAPACITY_IMAGES_CONFIG 指向该引擎实验目录下的五个固定镜像配置。它们各自初始化新安装，要求其他安装离线，保留原恢复与失败数据，复用离线 restore-public 夹具网络的未用地址；不使用主服务或用户云 API。实际 VPS 的资源/网络流程继续单独验收。

baseline 运行 8 个实际任务，记录控制面/运行/空闲和数据库/卷。idle 使用 1 分钟测试阈值，在第 8 个任务后检查禁用分支及七种合成资格状态，再等待真实 leased-worker 定时器停止；第 9 个实际任务验证自动唤醒与原 home 标记。合成 SQL 状态只用于边界条件，不当作真实人工交互/例程的端到端证据。

测试最终停止自己创建的 Compose/夹具及专用 VM，保留数据与证据。早期实验的入口就绪、保留子网冲突及 Docker host/none 网络的空 IPAM 信息错误均保留失败；修正测试边界后继续，不重跑已知 fake-IP 公网部署流程。

### 已通过的停机与唤醒

原始目录 `data/experiments/pa-linux-1792903976167/attempt-1792907342959`。受验 worker 为 `54af95cddc0d`，Web `600afb5d58dd`、工作站 `441e717eefd1`；应用协议仍为 0.9.0-dev，数据库 0011、guest 协议 2 不变。

- 第 8 个实际任务完成后，禁用分支在不可达数据库配置下返回空列表；七种 SQL 合成状态均未触发停机。
- 实际 leased-worker 定时器随后停止 viewer/guest；等待观测约 77 秒（含采样），epoch 从 32 变为 33，bootId 清空，容器与 home 保留。
- 停机采样只剩四个控制面容器。停机前 guest/viewer 展示内存为 906.8 / 31.94 MiB；第 9 个任务自动唤醒并再次交付四行/620，home 标记仍在。
- 共 9 次实际下载、63 次受控模型请求、8 个资源样本；最后一个采样的 guest/viewer 为 350.3 / 31.92 MiB。该差异仅为这组样本，尚未定位浏览器内存变化原因或建立长期上限。

原恢复安装与主服务均未启动或升级。两次成功实验共 17 个实际任务，网站登录旁路与模型延时均明确标记；真实登录保持、真实人工等待的长时间停机边界、慢桌面连接和长程负载另验。

## 5. 当前容量结论与后续

当前只有单工作站、受控小文件和短程样本。并发工作站、长任务、慢速桌面连接、真实模型/网站、磁盘逼近上限及长时间 DBOS 元数据保留仍未验收。保留失败、峰值、持续时长和现场条件，再决定规格与清理策略。

系统不会自动删除 home、成果或任务历史；空闲停机减少运行中的桌面消耗，磁盘保留和加密备份仍由明确的运维作业负责。避免以自动删掉用户文件来制造“容量稳定”的结果。
